# 01. ภาพรวมและกลยุทธ์โครงการ (Project Concept & Strategy)

## 1. ชื่อโครงการและนิยาม (Project Identity)
* **ชื่อโครงการ:** MEMO.ADT (Applied Digital Technology Student Showcase & Academic Archive)
* **หน่วยงาน:** สำนักวิชาเทคโนโลยีดิจิทัลประยุกต์ มหาวิทยาลัยแม่ฟ้าหลวง (School of Applied Digital Technology - ADT MFU)
* **โมเดลของระบบ:** **Hybrid Model (Showcase-First with Optional Academic Repository)**

---

## 2. ปรัชญาและขอบเขตของระบบ (Core Philosophy & Scope)

### 2.1 คลังผลงานคัดสรร ไม่ใช่ที่ทิ้งไฟล์ทั้งหมด (Curated Showcase, Not a Dump Site)
* **เป้าหมายที่แท้จริง:** ระบบนี้ **"ไม่ได้สร้างขึ้นมาเพื่อเก็บงานของนักศึกษาทุกคนทุกกลุ่มแบบ 100%"** แต่เน้นจัดเก็บ **"ผลงานที่ผ่านการคัดสรรจากอาจารย์แล้วว่ามีคุณภาพ โดดเด่น หรือมีคุณค่าคู่ควรแก่การเก็บบันทึกไว้"**
* **แก้ปัญหาพื้นที่จัดเก็บสูญหาย (Permanent Preservation vs. Ephemeral Cloud):**
  * แต่เดิมนักศึกษามักแชร์ลิงก์ Google Drive ซึ่งมีขีดจำกัดด้านพื้นที่จัดเก็บ (Storage Quota) พอนักศึกษาเรียนจบหรือพื้นที่เต็ม ไฟล์ใน Drive มักจะถูกลบหรือลิงก์เสีย ทำให้ผลงานสูญหายไปตลอดกาล
  * MEMO.ADT จึงทำหน้าที่เป็น **"บ้านถาวร (Permanent Archive)"** ให้กับผลงานคัดสรรเหล่านี้ โดยจัดเก็บรูปภาพ แกลเลอรี และไฟล์เอกสารสำคัญไว้บน Storage ของระบบโดยตรง ไม่พึ่งพาลิงก์ไดรฟ์ส่วนตัวของเด็กที่อาจหายไปในอนาคต

### 2.2 ปรัชญาการออกแบบ (Design Philosophy)

1. **Graceful Degradation (รองรับงานประวัติศาสตร์/งานเก่า):**
   * งานเก่าหลายชิ้นมีเพียงภาพ สกรีนช็อต หรือคลิปวิดีโอ แต่เล่มรายงานฉบับเต็มสูญหายไปตามกาลเวลา
   * ระบบต้องแสดงผลงานเหล่านี้ได้อย่างสวยงามเต็มภาคภูมิ โดยไม่แสดงแถบว่างหรือข้อความเตือนว่า "ขาดเอกสาร"
2. **Progressive Enrichment (ส่งเสริมงานรุ่นใหม่ให้ครบถ้วน):**
   * สำหรับผลงานใหม่ (เช่น Senior Capstone Projects ปีปัจจุบัน) สามารถแนบไฟล์เล่มรายงาน (PDF), บทคัดย่อ (Abstract TH/EN), โปสเตอร์, อาจารย์ที่ปรึกษา และลิงก์ Source Code / Live Demo ได้อย่างสมบูรณ์
   * เมื่อมีข้อมูลวิชาการครบ ระบบจะแสดงแท็บ/เซกชัน **"Academic & Technical Archive"** เสริมขึ้นมาอัตโนมัติ
3. **Multi-Disciplinary Presentation (รองรับความหลากหลายของ ADT):**
   * **MTA (Multimedia Technology and Animation):** ต้องการการแสดงผลภาพความละเอียดสูง วิดีโอ Showreel, WebGL/Game Embed
   * **SE (Software Engineering):** ต้องการ Live Demo, สถาปัตยกรรมระบบ, Tech Stacks, ลิงก์ GitHub
   * **CE & DCE (Computer Engineering & Digital and Communication Engineering):** ต้องการภาพฮาร์ดแวร์/IoT, แผนภาพวงจร, โปสเตอร์โครงงาน
   * **DTBI (Digital Technology for Business Innovation):** ต้องการ Business Model Canvas, แดชบอร์ดสรุปผลการวิเคราะห์ข้อมูล
   * **Postgraduate (DTT & CE Graduate):** งานวิจัยเชิงลึกระดับปริญญาโท-เอก (Digital Transformation Technology & Computer Engineering)

## 3. กลุ่มเป้าหมายและประเภทผู้ใช้งาน (Stakeholders & User Roles)

### 3.1 กลุ่มเป้าหมายและคุณค่าที่ได้รับ (Stakeholders & Value Proposition)

| กลุ่มผู้ใช้ | สิ่งที่ต้องการจากระบบ / คุณค่าที่ได้รับ | ฟังก์ชันหลักที่ตอบโจทย์ |
| :--- | :--- | :--- |
| **บุคคลภายนอก / ผู้ประกอบการ HR** | หาเด็กฝึกงาน/รับเข้าทำงาน ดูทักษะจริงของเด็ก ADT | หน้า Showcase ทันสมัย, ตัวกรอง Tech Stack, ช่องทางติดต่อ นศ. (LinkedIn, GitHub) |
| **นักเรียนมัธยม / ผู้ปกครอง** | ดูภาพรวมผลงานจริงเพื่อประกอบการตัดสินใจเข้าศึกษาต่อ | ผลงานเด่น (Featured), รางวัลการแข่งขัน (Hall of Fame), ผลงานแอนิเมชันและเกม |
| **นักศึกษาปัจจุบัน (รุ่นน้อง)** | ศึกษาแนวทางและหาไอเดียในการทำ Senior Project / งานวิชา | ค้นคว้าโครงงานย้อนหลัง, ศึกษาเครื่องมือ/ทฤษฎี, เปิดอ่านเล่มรายงาน (ถ้ามี) |
| **อาจารย์ / สำนักวิชา** | รายงานข้อมูลโครงงานสำหรับ AUN-QA และคลังเอกสารทางการ | Dashboard สรุปโครงงานแยกหลักสูตร, Export รายชื่อโครงงานและที่ปรึกษา |

### 3.2 การจำแนกประเภทผู้ใช้งานในระบบ (System User Roles)

แบ่งตามสิทธิ์และหน้าที่การใช้งานในระบบ:

1. 🟢 **Viewers (กลุ่มผู้เข้าชม):**
   * *ผู้ใช้:* บุคคลภายนอก, HR, นักเรียนมัธยม, ผู้ปกครอง, นักศึกษาปัจจุบัน (รุ่นน้อง)
   * *สิทธิ์:* **Read-Only** ค้นหา กรอง และดูผลงาน/วิดีโอ/เดโมได้อย่างอิสระ
2. 🔵 **Contributors (กลุ่มผู้ส่งผลงาน - ผ่าน Room Code):**
   * *ผู้ใช้:* นักศึกษาเจ้าของผลงาน (Senior Project, งานวิชา, งานแข่ง)
   * *สิทธิ์:* **Submit & Edit via Code** เข้าส่งงานผ่านรหัสห้อง (Room Code) หรือลิงก์จากอาจารย์ และแก้ไขงานตัวเองผ่าน Edit Token
3. 🟡 **Reviewers (กลุ่มอาจารย์ที่ปรึกษา / ผู้ตรวจ):**
   * *ผู้ใช้:* อาจารย์ที่ปรึกษาโครงงาน, อาจารย์ผู้สอน
   * *สิทธิ์:* **Room Owner & Reviewer** สร้างห้องส่งงาน (Generate Room Code), ตรวจรับงาน, กดส่งกลับให้เด็กแก้ (Return for Revision) หรือกดอนุมัติ (Approve)
4. 🔴 **Administrators (กลุ่มผู้ดูแลระบบและสำนักวิชา):**
   * *ผู้ใช้:* เจ้าหน้าที่สำนักวิชา ADT, ทีมงาน AUN-QA, ผู้ดูแลระบบ
   * *สิทธิ์:* **Super Admin** นำเข้าผลงานเก่า (Direct Add), จัดการ Master Data, ปักหมุดผลงานเด่น (Featured), และ Export รายงาน AUN-QA

## 4. กลไกการส่งงานและการแก้ไข (Submission & Revision Mechanism)

เพื่อลดภาระงานของอาจารย์ ป้องกันสแปม และยืดหยุ่นต่อการแก้ไข ระบบใช้ 2 กลไกสำคัญ:

1. **ระบบห้องส่งงาน (Room Code System):**
   * อาจารย์สร้างห้องระบุหลักสูตร (CE, DCE, SE, DTBI, MTA, DTT) และปีการศึกษา
   * ระบบสร้างรหัสห้อง (Room Code) ให้อาจารย์นำไปแจกนักศึกษา
   * นักศึกษากรอกข้อมูลผลงานโดยมีข้อมูลสาขาและอาจารย์ผูกไว้ให้อัตโนมัติ
2. **ระบบการแก้ไข 2 ช่องทาง (Dual-Path Correction):**
   * **Path 1 (อาจารย์แก้เอง):** อาจารย์/แอดมินมีสิทธิ์แก้ไขข้อมูลหรือไฟล์ได้โดยตรงตลอดเวลา สำหรับจุดผิดเล็กน้อย
   * **Path 2 (ส่งกลับให้เด็กแก้):** กรณีต้องแก้เล่มหรือไฟล์ใหญ่ อาจารย์กดส่งกลับ (Request Revision) ระบบออกรหัสแก้ไขกลุ่ม (Edit Token) ให้นักศึกษากดเข้าไปอัปเดตงานเดิมได้ทันที แม้จะเลยกำหนดเดดไลน์ไปแล้ว
