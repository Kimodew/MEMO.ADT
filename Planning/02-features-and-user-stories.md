# 02. ข้อกำหนดฟังก์ชันและฟีเจอร์ (Features & Requirements)

## 1. ฟังก์ชันฝั่ง Showcase (แกนหลัก - Core Experience)

### 1.1 หน้าแรก (Home & Explore)
* **Hero Banner / Spotlight:** สไลด์ผลงานเด่นที่ได้รับรางวัล หรือผลงานคัดสรรประจำปี (Curated / Award Winning)
* **Filter Bar อเนกประสงค์:**
  * **สาขาวิชา (Major / Program):** All, CE, DCE, SE, DTBI, MTA, DTT (Postgraduate)
  * **ประเภทผลงาน (Category):** Senior Project, Coursework (งานในวิชา), Competition / Awarded (งานแข่งขันภายนอก), Research
  * **ปีการศึกษา (Academic Year):** เช่น 2567, 2566, 2565...
  * **Tech Stacks / Tags:** ค้นหาตามเครื่องมือ เช่น Unity, Unreal Engine, React, Flutter, Python, IoT, Blender, AI/ML
* **Grid Card แสดงผลงาน:**
  * ภาพหน้าปก (Cover Image) ขนาดใหญ่สไตล์ Behance / Dribbble
  * ชื่อผลงาน (Project Title)
  * แท็กสาขา และ Tech Stack ย่อ
  * Badges แสดงสถานะพิเศษ เช่น `Award Winner`, `Senior Capstone`, `Has Report PDF`

### 1.2 การจัดแสดงผลงานแบบ Quick Modal Viewer & ระบบ Deep Linking (Project Detail Experience)
ยึดระบบ **Quick Modal Viewer** เป็นแกนหลักในการแสดงผลงานฉบับเต็ม เพื่อความรวดเร็ว ไหลลื่น ไม่ต้องโหลดเปลี่ยนหน้า (Zero Page Reload Friction):

* **โครงสร้างการแสดงผลใน Quick Modal:**
  * **Media Showcase:**
    * แกลเลอรีภาพความละเอียดสูง (Carousel / Lightbox)
    * Embedded Video (YouTube / Vimeo / Google Drive player) สำหรับดูคลิปเดโม หรือคลิปแอนิเมชัน
    * Web Game / Interactive Embed (ถ้ามี เช่น itch.io iframe หรือ Unity WebGL)
  * **Action Links:**
    * ลิงก์ `Live Demo` (เปิดดูเว็บจริง)
    * ลิงก์ `GitHub Repository` / Source Code
    * ลิงก์ `Download Game/App` (Google Drive, App Store, Play Store)
  * **ข้อมูลทีมผู้พัฒนา (Project Creators):**
    * ชื่อ-นามสกุล, รหัสนักศึกษา (แสดงเฉพาะปีการศึกษาถ้าต้องการความเป็นส่วนตัว)
    * สาขาวิชา
    * ลิงก์ช่องทางติดต่อ (LinkedIn, GitHub, ArtStation, Personal Website)

* **ระบบปุ่มแชร์และ Deep Linking (Share Button & Direct Inbound URL):**
  * **ปุ่มแชร์ผลงาน (Share Button):** ติดตั้งอยู่มุมขวาบนข้างปุ่มปิด `✕` ใน Quick Modal
    * **Desktop:** คลิกแล้วคัดลอกลิงก์ผลงานฉบับเต็มลง Clipboard ทันที พร้อมแสดง Toast แจ้งเตือน `✓ คัดลอกลิงก์ผลงานแล้ว!`
    * **Mobile:** เชื่อมต่อกับ Web Share API ของระบบปฏิบัติการเพื่อแชร์ไปยังแอปภายนอก (LINE, Facebook, X, Messages) ได้ในคลิกเดียว
  * **การซิงก์ URL อัตโนมัติ (Dynamic History Sync):** เมื่อเปิด Modal เบราว์เซอร์จะอัปเดต URL เป็น `?project={slug}` หรือ `/project/{slug}` ผ่าน HTML5 History API ทันที
  * **การเข้าชมผ่านลิงก์ตรง (Direct Inbound Landing):** เมื่อนักศึกษานำลิงก์ไปใส่ใน Resume/Portfolio แล้วมีผู้คลิกเข้ามา เว็บไซต์จะเปิดหน้าแรกพร้อมเด้งเปิด Quick Modal ของโครงงานนั้นขึ้นมาให้อัตโนมัติทันที โดยไม่ต้องไปค้นหาเอง

## 2. ฟังก์ชันฝั่ง Academic Repository (ส่วนเสริม - Optional Academic Layer)

ส่วนนี้จะปรากฏเฉพาะในผลงานที่มีการระบุข้อมูลทางวิชาการ (ไม่บังคับสำหรับงานเก่า):

### 2.1 ข้อมูลวิชาการและเอกสาร (Academic Section)
* **บทคัดย่อ (Abstract):** รองรับภาษาไทย และภาษาอังกฤษ
* **อาจารย์ที่ปรึกษา (Advisor) & กรรมการสอบ (Committee):**
  * แสดงชื่ออาจารย์ที่ปรึกษาหลัก และที่ปรึกษาร่วม (คลิกดูโครงงานทั้งหมดที่อาจารย์ท่านนี้ดูแลได้)
* **คลังเอกสารดาวน์โหลด (Academic Assets):**
  * เล่มรายงานโครงงานฉบับสมบูรณ์ (Full Thesis / Capstone Report PDF)
  * โปสเตอร์นำเสนอโครงงาน (Poster PDF / High-res Image)
  * เอกสารประกอบอื่นๆ เช่น สไลด์นำเสนอ (Slide Presentation)
* **การควบคุมสิทธิ์เอกสาร (Document Access Control):**
  * เลือกได้ว่าให้ดาวน์โหลดแบบ `Public` หรือต้องล็อกอินด้วยอีเมลนักศึกษา MFU (`@lamduan.mfu.ac.th` / `@mfu.ac.th`)

## 3. ฟังก์ชันระบบจัดการและการส่งผลงาน (Management & Submissions)

### 3.1 ระบบห้องส่งผลงาน (Submission Room System)
สำหรับอาจารย์และเจ้าหน้าที่ใช้ควบคุมรอบการส่งงานอย่างเป็นระเบียบ:
* **การสร้างห้องส่งงาน (Create Room):**
  * กำหนดชื่อห้อง (เช่น Senior Project วิศวกรรมซอฟต์แวร์ ภาค 2/2567)
  * ล็อกค่าอัตโนมัติ: สาขาวิชา (CE, DCE, SE, DTBI, MTA, DTT), ปีการศึกษา, อาจารย์ที่ปรึกษาเริ่มต้น
  * กำหนดเดดไลน์วันและเวลาปิดรับผลงาน (Deadline)
* **การสร้างรหัสห้องและลิงก์ (Room Code & Magic Link):**
  * ระบบสุ่มรหัสสั้น (เช่น `SE-2567-X9`) พร้อมสร้างลิงก์สำหรับคลิกเข้าส่งงานได้ทันที ให้อาจารย์นำไปแชร์ในกลุ่มนักศึกษา
* **แดชบอร์ดตรวจสอบรายกลุ่ม (Room Overview):**
  * อาจารย์เปิดดูความคืบหน้าของห้อง เห็นรายชื่อทุกกลุ่มที่ส่งงานเข้ามา พร้อมสถานะ `รอตรวจ (Pending)` หรือ `อนุมัติแล้ว (Approved)`

---

### 3.2 ระบบเพิ่มผลงานของนักศึกษาด้วย Room Code (Student Submission via Room Code)
* **ปรัชญาและคำที่ใช้บน UI (Empowering Terminology):** ใช้คำว่า **`เพิ่มงานด้วย Room Code`** (แทนคำว่า "ส่งงาน" เพื่อให้ความรู้สึกของการนำผลงานเข้าสู่คลังจัดแสดงและเผยแพร่นวัตกรรมสู่สากล ไม่ใช่แค่การส่งการบ้าน)
* **การเข้าใช้งาน:** นักศึกษากรอกรหัสห้อง (Room Code) ผ่านปุ่มบน Header หรือคลิกลิงก์จากอาจารย์
* **ขั้นตอนการเพิ่มผลงาน (Multi-Step Form):**
  1. **ข้อมูลโครงงาน:** ชื่อไทย-อังกฤษ, คำอธิบายสั้นๆ (ข้อมูลสาขาและปีจะถูกล็อกตามห้องไว้ให้อัตโนมัติ ไม่ต้องกรอกซ้ำ)
  2. **สื่อจัดแสดง (Showcase Assets):** รูปภาพหน้าปก, ภาพแกลเลอรี, ลิงก์วิดีโอเดโม (YouTube/Vimeo), ลิงก์ Live Demo, GitHub
  3. **เอกสารวิชาการ (Academic Assets - *Optional*):** บทคัดย่อ TH/EN, เล่มรายงาน PDF, โปสเตอร์
  4. **ข้อมูลสมาชิกในกลุ่ม:** ชื่อ-นามสกุล, รหัสนักศึกษา, บทบาทในโปรเจกต์, ลิงก์ Portfolio/LinkedIn
* **รหัสแก้ไขเฉพาะกลุ่ม (Project Edit Token):** เมื่อส่งงานสำเร็จ ระบบจะออกรหัสเฉพาะกลุ่มสำหรับใช้กลับเข้ามาแก้ไขงานได้ในอนาคต

---

### 3.3 กลไกการแก้ไขผลงาน (Dual-Path Correction Flow)
รองรับกรณีข้อมูลผิดพลาดหรือต้องการแก้ไข แม้ว่าจะเลยกำหนดเดดไลน์ไปแล้ว:

* **เส้นทางที่ 1: อาจารย์/แอดมินแก้ไขเองโดยตรง (Direct Edit)**
  * อาจารย์หรือแอดมินกดปุ่ม Edit บนหน้าผลงานเพื่อแก้คำผิด ปรับเปลี่ยนรูปภาพ หรืออัปเดตไฟล์เล่มรายงานได้ทันทีโดยไม่ต้องผ่านเด็ก
* **เส้นทางที่ 2: ส่งกลับให้นักศึกษาแก้ไข (Return for Revision)**
  * อาจารย์กดปุ่ม "ส่งกลับให้แก้ไข" พร้อมระบุหมายเหตุสิ่งที่ต้องแก้
  * นักศึกษาใช้ลิงก์เดิม หรือกรอก `Project Edit Token` เพื่อเข้าไปอัปเดตไฟล์เดิมได้ทันทีโดยไม่ต้องสร้างงานใหม่ซ้ำซ้อน

---

### 3.4 การนำเข้าผลงานตรงสำหรับงานเก่า (Direct Add for Historical Projects)
* แอดมินและอาจารย์มีปุ่ม `+ Direct Add Project` เพิ่มผลงานเข้าสู่ระบบได้ทันทีโดยไม่ต้องผ่านระบบห้อง
* เหมาะสำหรับการนำเข้าผลงานของรุ่นพี่ในอดีต (Historical Archive) ที่มีเฉพาะภาพหรือข้อมูลบางส่วน
